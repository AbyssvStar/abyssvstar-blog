# 07 前端与设计（施工图）

## 0. 实现现状（2026-10）

> 本节只记"实际做出来的"和设计稿的差异；下面各节的取舍与理由仍然有效。

- **技术栈落地**：Next 16（App Router，`output: 'export'`）+ Tailwind 4 + Shiki 4（构建期高亮，客户端零高亮 JS）。设计稿写的 shadcn/ui 没有引入 —— 页面量小，直接用 CSS + 原生元素更省。
- **页面**：首页 / 文章列表 / 文章详情 / 动态列表与详情 / 标签列表与详情 / 归档 / 关于 / 搜索 / RSS / sitemap / robots / 404。搜索页、评论和阅读量都是客户端组件。
- **关于页**：站名、简介、关于页正文、封面图、头像都来自后台的站点配置（`siteConfig` 进导出），不再写死在代码里；另有头像彩蛋、Konami、右下角隐藏终端。
- **视觉方向**：深蓝黑 + 单一冷色强调；首页满屏星野（三块 canvas，可拖动生成星系）、全站粒子、指针柔光、点击扩散/迸发、卡片倾斜。
- **分页与标签筛选**在浏览器里做：静态导出没有服务端，但全部文章都在同一个 HTML 里，爬虫拿得到。
- **代码高亮**：Shiki 双主题只产出 `--shiki-dark`，浅色那套写在内联 `style` 里；所以浅色侧不写覆盖，深色侧用 `!important` 取 `--shiki-dark`。

## 3. 设计规范

### 3.1 双主题（默认深色）

```css
:root[data-theme="dark"] {
  --bg:            #0a0a0b;
  --bg-elevated:   #141416;
  --border:        #26262b;
  --text:          #e8e8ea;
  --text-muted:    #9a9aa3;
  --accent:        #6ea8fe;
  --accent-glow:   rgba(110, 168, 254, .35);
}
:root[data-theme="light"] {
  --bg:            #ffffff;
  --bg-elevated:   #f7f7f8;
  --border:        #e5e5e8;
  --text:          #18181b;
  --text-muted:    #6b6b73;
  --accent:        #2563eb;
}
```

| 规则 | 说明 |
|---|---|
| 默认主题 | 深色；首次访问尊重 `prefers-color-scheme` |
| 持久化 | `localStorage` + **首屏内联脚本**设置 `data-theme` |
| **防闪烁（FOUC）** | 内联脚本必须尽早执行。静态导出的实现放在 `<body>` 第一个元素中，React 不接管，浏览器解析到它时就会执行 |
| 切换 | 顶栏图标按钮，切完写 `localStorage` |

### 3.3 文章页结构

```
┌─ 阅读进度条（顶部固定，2px 高）────────────────┐
├──────────────┬───────────────────────────────┤
│              │  标题 / 日期 / 阅读时长 / 标签    │
│  左侧 TOC    │  ─────────────────────────    │
│  （sticky，  │  正文                           │
│   滚动跟随   │   · 代码块带复制按钮             │
│   当前节高亮）│   · 图片带尺寸占位（防抖动）      │
│              │  ─────────────────────────    │
│              │  相关文章（向量相似度）           │
│              │  评论区                          │
└──────────────┴───────────────────────────────┘
移动端：TOC 折叠为右下角浮动按钮
```

| 要素    | 实现要点                                                              |
| ----- | ----------------------------------------------------------------- |
| TOC   | **构建时从 Markdown AST 生成**，不运行时解析                                   |
| 滚动高亮  | **`IntersectionObserver`，不用 `scroll` 事件**（性能差一个量级）                |
| 代码复制  | 复制按钮 + `navigator.clipboard`，失败回退 `execCommand`                   |
| 阅读进度条 | `scroll` 事件 + `requestAnimationFrame` 节流（只有这一处用 scroll）           |
| TOC 激活态 | 左侧 2px accent 实线（`inset box-shadow`，不改宽度以免文字位移）+ 文字提亮；**不要只把文字变蓝**，滚动时根本找不着 |
| 顶栏 | 常驻 `color-mix(bg 72%)` + `blur(14px)`，滚动后加深到 84% 并把底边线从 6% 提到 11%；底边线常驻，不然文字压过内容会打架 |
| 相关文章  | 客户端 fetch `/api/v1/posts/{slug}` 返回的 `related` 字段（向量相似度，零 LLM 成本） |
| 图片    | 必须写 `width` / `height`，**否则 CLS 会很难看**                            |

### 3.4 动态页与留言区

```
动态列表：年月分隔（2026 / 10 —— 4 条）+ 日志行
  ┌ 4.6rem ┬ 正文（≤46rem）─────────────── #07 ┐
  │  23     │ 一句话动态                       │
  │ 周五... │ 图片：定高 cover（1 张 17rem）      │
  └─────────┴ 查看动态 →                        ┘
单条详情：左侧 7.2rem 日期轨 + 右侧正文（同一块低饱和面板）
留言：发丝线分隔的访客簿，不套卡片盒子
```

| 要素 | 约定 |
|---|---|
| 动态列表 | **不用卡片**：卡片画出右边界，短动态的右半就会被读成空白；改成日期栏 + 正文的日志行，右端用 `#编号` 压住 |
| 月份分隔 | 由 `publishedAt` 在构建期分组，`Reveal` 逐段入场 |
| 列表图片 | **单图按原比例展开**（`width: 100%; height: auto`），正常横图不裁上下；2–4 张才用定高 + `cover`（2 张 11rem、3 张 9rem、4 张 8rem），超过 4 张角标 `+N`。**不给图加描边或底板**——紧挨着日期脊线，两道线会互相打架 |
| 竖版长图 | 单张且 `height/width ≥ 1.25`：框高 `clamp(18rem, 40vw, 30rem)`、图片居中、`height: calc(100% + 2.4rem)`（上下各裁 1.2rem 的零头）。左右留出来的就是页面底色，**不要给框上底**——一上色就变成一块黑框贴在页面上 |
| 详情图片 | **详情页是看图的，不要为了对齐把图缩小**：`max-width: 100%`，只受列宽和 `max-height: 34rem` 约束。**多图一律竖排**（并排两列会把竖拍图裁成窄条）；单图 34rem、多图 30rem、`width: auto`，**不要 `max-height: none`**（竖图会撑到两三千像素） |
| 正文行长 | 一律 `var(--readw)`（46rem），动态正文也不放宽 |
| 分隔线 | 这一块用局部 token `--line`（`color-mix(in srgb, var(--text) 17%, transparent)`）；全站的 `--border-soft` 在亮色下接近纯白，留言会糊成一片 |
| 列表脊线 | 日期栏右侧一条竖线，贯穿整个列表；窄屏日期栏变成一行时隐藏 |
| 留言排序 | 按时间**正序**排（1 楼最早，行尾显示「n 楼」）；接口默认给的是倒序，前端 flip 之后再渲染 |
| 留言列表 | `<ol>` + 发丝线，方形首字母头像 2.1rem（窄屏 1.9rem）；名字与相对时间同行开头，「n 楼」顶到行的右端；完整时间放 `title` |
| 留言顺序 | **两个页面统一：表单在最前，评论列表在后**（先写后读，别让留言框沉到页尾） |
| 留言表单（文章页） | `variant="card"`：**一整块平面卡片**（实色底 `light-dark(#fff, #233042)` + 1px 描边 + 8px 圆角），内部只靠发丝线分区——上面两格「昵称 / 邮箱」并排（中缝竖线），中间整块 textarea，底部通栏放字符数与按钮。输入框本身无边框无底色，靠卡片给面 |
| 留言表单（动态详情） | `variant="thread"`：不套卡片，是一条带字段名的横带，输入框浅底色 + 发丝边框 + 5px 圆角，focus 加 3px 淡环 |
| 字段名 | **必须留可见的字段名**（昵称 / 邮箱 / 内容），不能只靠 placeholder——placeholder 一输入就没了，读者回头不知道自己填的是哪格 |
| 提交按钮 | 两个变体共用幽灵按钮（透明底 + 26% 描边 + `→`），5px 圆角；不要 accent 填充——满屏暗底里一块亮蓝像警告条 |
| 文章页留言 | 落在 `.glass` 面板上时**不要再套一层毛玻璃或深色底板**，玻璃叠玻璃只会显脏；卡片本身就是那一层的面。卡片底色要比面板**明显亮一档**，太接近就分不出边界 |
| 空状态 | 一行极淡文字，**不用虚线框**（虚线在视觉语言里读作"未完成"） |
| 页面标题 | 动态没有标题，`<title>` 取正文头一句（`excerpt`，26 字）；**不要用自增 id** |
| 组件复用 | `CommentSection` 同时用于文章页与动态详情页，改样式要保证在 `.glass` 面板里也成立 |

## 4. 数据获取边界

静态导出意味着**所有构建时获取的数据都被"冻结"成 HTML**。所以边界必须画清楚：

> **判断标准只有一条：作者写的东西进 HTML，读者写的东西走接口。**

| 场景 | 方式 | 原因 |
|---|---|---|
| 文章 / 动态 / 标签 / 归档 | **构建时** `fetch('/api/v1/export')`（带 `If-None-Match`） | **作者写的**，只在发布时变 |
| 评论列表 | 客户端 fetch | **读者写的**，随时新增 |
| 评论提交 | 客户端 POST | 同上 |
| 评论**条数**显示 | 客户端 fetch | 跟评论列表一起返回，**绝不在 HTML 里写死条数** |
| 阅读量**打点** | 客户端 POST（fire-and-forget，失败静默） | 每篇文章都要打 |
| 阅读量**显示** | 客户端 fetch | **绝不能进静态 HTML** |
| 搜索 | 客户端 fetch | 用户输入驱动 |
| 相关文章 | 客户端 fetch | 依赖向量相似度，构建时算不出来 |
| AI 问答 | SSE 流式 | —— |

## 5. SEO

| 项                         | 做法                                |
| ------------------------- | --------------------------------- |
| title / description       | 构建时从内容生成                          |
| Open Graph / Twitter Card | 每篇文章构建时生成 OG 图                    |
| **JSON-LD**               | 文章页输出 `Article` 结构化数据（作者、发布时间、封面） |
| `sitemap.xml`             | 构建时生成，**排除私密与归档内容**               |
| `rss.xml`                 | **全文 RSS**（不是摘要——技术读者要能全文阅读器里读）   |
| `robots.txt`              | 允许全部，`Sitemap:` 指向站点地图            |
| canonical                 | 每页输出                              |
| 归档内容                      | 保留页面但加 `noindex`                  |
| 站点地图                      | `/sitemap` 可读页面（可选，后期加）           |

## 7. 留言板（前端）

```
位置：文章页和动态详情页底部
字段：昵称 / 邮箱（可选）/ 内容 / 蜜罐字段（隐藏）
提交后：「已提交，等待审核」
```

前端要做：

1. **蜜罐字段** —— 用 `position:absolute; left:-9999px` 而不是 `type="hidden"`（**部分机器人会主动跳过 hidden 字段**）
2. **记录表单渲染时间戳**，随提交一起发（服务端校验 < 3 秒 → 判 SPAM）
3. 内容长度前端校验（≤ 1000 字）

## 8. 目录与部署

前端都在仓库的 `frontend/` 下，是**两个独立应用**：

| 目录 | 是什么 | 产物 | 什么时候重建 |
|---|---|---|---|
| `frontend/admin/` | 后台 UI：登录 / 列表 / 编辑器 / 实时预览 / 发布 | 静态 JS 外壳 | **后台代码变了才重建**，与内容无关 |
| `frontend/site/` | 公开站（`output: 'export'`） | 冻结的 HTML | **内容发布时**触发（webhook → Actions） |

两者都由 Nginx 直发静态文件，和应用容器在同一台机器：

```nginx
location /admin/api/ { proxy_pass http://127.0.0.1:8080; }
location /admin/     { root /srv/static; }
location /api/       { proxy_pass http://127.0.0.1:8080; }
location /media/     { proxy_pass http://minio:9000/media/; }
location /           { root /srv/static; }
```

前缀匹配取最长，所以 `/admin/api/**` 不会被 `/admin/` 的静态规则吃掉

**两者取数方式的根本差异**：

- 公开站在**构建时**调 `/api/v1/export`，把内容烤进 HTML
- 后台在**运行时**由浏览器调 `/admin/api/**` 拿实时数据

所以后台不需要 SSG、不需要 SEO、也不需要那套静态导出的约束。

### 8.1 代码高亮放在前端

后端**不引入任何语法高亮依赖**。做法是：

- 后端只负责把围栏代码块渲染成 `<pre><code class="language-xxx">`
- 公开站**构建时**用 Shiki 处理这些代码块 —— Shiki 可以直接对渲染好的 HTML 操作，
  **不需要 Markdown 原文**，所以 `/api/v1/export` 的契约不用加字段
- 客户端零 JS，守住 §4 那条 40KB 预算

后台页面不受 §4 的预算约束（只有一个人用），需要颜色的话在浏览器里高亮即可。
