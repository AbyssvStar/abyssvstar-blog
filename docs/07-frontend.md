## 1. 技术栈

| 项 | 选型 |
|---|---|
| 框架 | **Next.js（App Router）+ TypeScript**，`output: 'export'` 静态导出 |
| 样式 | Tailwind CSS v4 |
| 组件 | shadcn/ui（复制式引入，非运行时依赖） |
| 图标 | lucide-react |
| 代码高亮 | **Shiki**（构建时高亮，客户端零 JS） |
| 动画 | CSS + Tailwind transitions 为主；首页可用 Framer Motion，**文章页禁止引入** |
| 字体 | 中文走系统栈，英文/代码用可变字体子集 |

字体很耗费性能：

```css
--font-sans: system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: "JetBrains Mono", ui-monospace, monospace;
```

> **绝不加载完整中文字体文件**（动辄 3–8MB）。中文用系统字体栈，只有英文和代码用 Web 字体，且必须做子集化。

## 2. 路由与信息架构

```
/                       首页（炫酷 landing：hero + 最近动态 + 最新文章）
/posts                  文章列表（分页 + 标签筛选）
/posts/[slug]           文章详情
/archive                时间归档（按年月）
/about                  关于（正文来自后台的站点配置，Markdown 编辑、保存即重建）
/search                 搜索
/notes                  短动态列表（**存在，但不进一级导航**）
/notes/[id]             单条动态详情
/rss.xml                构建时生成
/sitemap.xml            构建时生成
```

**一级导航只有四项**：首页 / 文章 / 归档 / 关于。搜索放顶栏图标。

### 2.1 短动态的入口（已定方案）

导航四项里没有短动态的位置，但它必须有显眼入口。方案：

> **首页 hero 下方直接放「最近动态」区块**（3–5 条）。
> 导航保持四项干净，动态出现在全站最显眼的位置；`/notes` 列表页和 `/notes/{id}` 详情页都存在，只是不占导航项。

## 3. 设计规范

### 3.1 双主题（默认深色）

```css
:root[data-theme="dark"] {
  --bg:            #0a0a0b;
  --bg-elevated:   #141416;
  --border:        #26262b;
  --text:          #e8e8ea;
  --text-muted:    #9a9aa3;
  --accent:        #6ea8fe;
  --accent-glow:   rgba(110, 168, 254, .35);
}
:root[data-theme="light"] {
  --bg:            #ffffff;
  --bg-elevated:   #f7f7f8;
  --border:        #e5e5e8;
  --text:          #18181b;
  --text-muted:    #6b6b73;
  --accent:        #2563eb;
}
```

| 规则 | 说明 |
|---|---|
| 默认主题 | 深色；首次访问尊重 `prefers-color-scheme` |
| 持久化 | `localStorage` + **首屏内联脚本**设置 `data-theme` |
| **防闪烁（FOUC）** | 内联脚本必须放在 `<head>` 里、在任何样式生效前执行。**这一步不做，每次刷新都会白闪一下** |
| 切换 | 顶栏图标按钮，切完写 `localStorage` |

### 3.2 首页结构（炫酷 landing）

```
┌─────────────────────────────────────────────┐
│  顶部导航（吸顶；滚动后加背景模糊 + 细边框）     │
│  AbyssvStar     首页 文章 归档 关于    [搜索][主题]│
├─────────────────────────────────────────────┤
│                                              │
│   HERO                                       │
│   · 背景：CSS 渐变 + 细网格 + 缓慢流动的光晕     │
│   · 大字标题 + 一句自我介绍                     │
│   · 三个数据：文章数 / 总字数 / 运行天数          │
│   · 滚动提示                                  │
│                                              │
├─────────────────────────────────────────────┤
│   最近动态（短动态 3–5 条，横向卡片）            │
├─────────────────────────────────────────────┤
│   最新文章（3–6 篇，卡片网格）                  │
├─────────────────────────────────────────────┤
│   页脚：导航 / RSS / 站点信息                    │
└─────────────────────────────────────────────┘
```

**"炫酷"的实现原则（2026-10 修订：用户要求更"堆料"，轻量动效放开了）**：

| 做 | 不做 |
|---|---|
| CSS 渐变、光晕、细网格 | ❌ 大图背景、视频背景 |
| 指针跟随柔光、卡片轻微倾斜（只动 transform/opacity，走合成层） | ❌ 滚动劫持（scroll-jacking） |
| 自写的 canvas 动效（落叶之类：数量少、只在标签页可见时跑） | ❌ 引第三方粒子/滚动动画库（体积与可控性都不划算） |
| hover 抬升、入场淡入、导航下划线扫出 | ❌ 正文区域的持续性动画（那里要保持安静） |

**动效的四条约束（不能破）**：

- 一律尊重 `prefers-reduced-motion: reduce`：开了就**不挂**这些效果，不是"关掉动画"而是根本不渲染
- 动效只在背景层与首页出现；**文章正文区域保持安静**，只保留图片 hover 与灯箱
- **首屏 LCP < 1.5s 仍是硬指标**：动效不得阻塞首屏（canvas 在 rAF 里画，不参与 LCP 计算）
- 只允许 `transform` / `opacity` 参与动画，禁止动 width/height/top/left（会触发重排）

**理由**：你说的"炫酷"如果靠大图和视频实现，会同时撞上三件事——2H4G 的带宽、首屏加载时间、以及我们定下的"服务器零渲染开销"原则。**纯 CSS 能做到的视觉强度已经远超预期，而且首屏 LCP 能压到 1.5s 以内。**

**首屏 LCP < 1.5s 是硬指标**，不是愿望。

### 3.3 文章页结构

```
┌─ 阅读进度条（顶部固定，2px 高）────────────────┐
├──────────────┬───────────────────────────────┤
│              │  标题 / 日期 / 阅读时长 / 标签    │
│  左侧 TOC    │  ─────────────────────────    │
│  （sticky，  │  正文                           │
│   滚动跟随   │   · 代码块带复制按钮             │
│   当前节高亮）│   · 图片带尺寸占位（防抖动）      │
│              │  ─────────────────────────    │
│              │  相关文章（向量相似度）           │
│              │  评论区                          │
└──────────────┴───────────────────────────────┘
移动端：TOC 折叠为右下角浮动按钮
```

| 要素 | 实现要点 |
|---|---|
| TOC | **构建时从 Markdown AST 生成**，不运行时解析 |
| 滚动高亮 | **`IntersectionObserver`，不用 `scroll` 事件**（性能差一个量级） |
| 代码复制 | 复制按钮 + `navigator.clipboard`，失败回退 `execCommand` |
| 阅读进度条 | `scroll` 事件 + `requestAnimationFrame` 节流（只有这一处用 scroll） |
| 相关文章 | 客户端 fetch `/api/v1/posts/{slug}` 返回的 `related` 字段（向量相似度，零 LLM 成本） |
| 图片 | 必须写 `width` / `height`，**否则 CLS 会很难看** |

## 5. 数据获取边界

静态导出意味着**所有构建时获取的数据都被"冻结"成 HTML**。所以边界必须画清楚：

> **判断标准只有一条：作者写的东西进 HTML，读者写的东西走接口。**

| 场景 | 方式 | 原因 |
|---|---|---|
| 文章 / 动态 / 标签 / 归档 | **构建时** `fetch('/api/v1/export')`（带 `If-None-Match`） | **作者写的**，只在发布时变 |
| 评论列表 | 客户端 fetch | **读者写的**，随时新增 |
| 评论提交 | 客户端 POST | 同上 |
| 评论**条数**显示 | 客户端 fetch | 跟评论列表一起返回，**绝不在 HTML 里写死条数** |
| 阅读量**打点** | 客户端 POST（fire-and-forget，失败静默） | 每篇文章都要打 |
| 阅读量**显示** | 客户端 fetch | **绝不能进静态 HTML** |
| 搜索 | 客户端 fetch | 用户输入驱动 |
| 相关文章 | 客户端 fetch | 依赖向量相似度，构建时算不出来 |
| AI 问答 | SSE 流式 | —— |

## 6. SEO

| 项 | 做法 |
|---|---|
| title / description | 构建时从内容生成 |
| Open Graph / Twitter Card | 每篇文章构建时生成 OG 图 |
| **JSON-LD** | 文章页输出 `Article` 结构化数据（作者、发布时间、封面） |
| `sitemap.xml` | 构建时生成，**排除私密与归档内容** |
| `rss.xml` | **全文 RSS**（不是摘要——技术读者要能全文阅读器里读） |
| `robots.txt` | 允许全部，`Sitemap:` 指向站点地图 |
| canonical | 每页输出 |
| 归档内容 | 保留页面但加 `noindex` |
| 站点地图 | `/sitemap` 人类可读页面（可选，后期加） |

## 7. 留言板（前端）

```
位置：文章页底部（第一版只做文章页）
字段：昵称 / 邮箱（可选）/ 内容 / 蜜罐字段（隐藏）
提交后：「已提交，等待审核」
```

前端要做：

1. **蜜罐字段** —— 用 `position:absolute; left:-9999px` 而不是 `type="hidden"`（**部分机器人会主动跳过 hidden 字段**）
2. **记录表单渲染时间戳**，随提交一起发（服务端校验 < 3 秒 → 判 SPAM）
3. 内容长度前端校验（≤ 1000 字）

## 8. 目录与部署

前端都在仓库的 `frontend/` 下，是**两个独立应用**：

| 目录 | 是什么 | 产物 | 什么时候重建 |
|---|---|---|---|
| `frontend/admin/` | 后台 UI：登录 / 列表 / 编辑器 / 实时预览 / 发布 | 静态 JS 外壳 | **后台代码变了才重建**，与内容无关 |
| `frontend/site/` | 公开站（`output: 'export'`） | 冻结的 HTML | **内容发布时**触发（webhook → Actions） |

两者都由 Nginx 直发静态文件，和应用容器在同一台机器：

```nginx
location /admin/api/ { proxy_pass http://127.0.0.1:8080; }
location /admin/     { root /srv/static; }
location /api/       { proxy_pass http://127.0.0.1:8080; }
location /media/     { proxy_pass http://minio:9000/media/; }
location /           { root /srv/static; }
```

前缀匹配取最长，所以 `/admin/api/**` 不会被 `/admin/` 的静态规则吃掉

**两者取数方式的根本差异**：

- 公开站在**构建时**调 `/api/v1/export`，把内容烤进 HTML
- 后台在**运行时**由浏览器调 `/admin/api/**` 拿实时数据

所以后台不需要 SSG、不需要 SEO、也不需要那套静态导出的约束。

### 8.1 代码高亮放在前端

后端**不引入任何语法高亮依赖**。做法是：

- 后端只负责把围栏代码块渲染成 `<pre><code class="language-xxx">`
- 公开站**构建时**用 Shiki 处理这些代码块 —— Shiki 可以直接对渲染好的 HTML 操作，
  **不需要 Markdown 原文**，所以 `/api/v1/export` 的契约不用加字段
- 客户端零 JS，守住 §4 那条 40KB 预算

后台页面不受 §4 的预算约束（只有一个人用），需要颜色的话在浏览器里高亮即可。
